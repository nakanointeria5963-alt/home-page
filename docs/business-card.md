# 名刺仕様 — ROGUE PINK

印刷所にそのまま渡せるように、決まったことをまとめたもの。

入稿データは生成済み。**`scripts/build-card.py` が唯一の出どころ**で、
PDFはそこから作り直せる(フォントは `@fontsource/noto-sans-jp` を使う)。

## いま使う入稿データ(2026-08-18 確定・案B)

| 用途 | ファイル |
| --- | --- |
| 表・箔押しの版 | `public/brand/card-front-foil-plate.pdf` |
| 裏・ホワイトインク | `public/brand/card-back-white.pdf` |
| 裏・ネオンピンク | `public/brand/card-back-pink.pdf` |

**3つとも 91 × 55mm(仕上がりサイズ)・グレースケール。**
黒い紙に刷るので背景を印刷せず、端まで色が乗らない。
そのため**塗り足しもトンボも要らない**(LEDA は「トンボを付けられない場合は
仕上りサイズで入稿」と回答)。

⚠ `card-front-print.pdf` `card-back-print.pdf` は**案A(白い紙)用の旧データ。
もう使わない。**97 × 61mm で、RGB のまま。

## 考え方

事業が複数あるので、名刺に事業内容は書かない。事業が増えるたび刷り直しになるうえ、
情報が多いと読まれない。**名刺はサイトへの入り口**と割り切り、
詳しいことは `roguepink.com` 側で更新していく。

### 名刺とサイトで言葉を変える

同じ文言を両方に置くと、QRを読んだ人が「さっき読んだのと同じ」に着地して、
わざわざ読み取った意味がなくなる。そこで役割を分ける。

| 場所 | 言葉 |
| --- | --- |
| 名刺 | はじまりは、「ありがとう」でした。 |
| サイト | ありがとうと言ってもらいたい。そして、ありがとうと言いたい。 |

名刺が問いを立てて、サイトが答える。QRを読む行為が「ページをめくる」ことになる。

2行の長さは揃っていない(14.0mm と 25.7mm)。揃える案も検討したが、
短い1行目から長い2行目へ落ちる段差が「ありがとう」を目立たせているため、
**意図的にこのままにしている**。整えると平らになって言葉が埋もれる。

## 印刷・加工

「かっこよさ」はデザインより紙と加工で決まる。

- 用紙:220kg 以上。薄いと安っぽく見える
- おすすめ:**マットコート + 表のロゴをピンクの箔押し**
  - 版データ:`public/brand/card-front-foil-plate.pdf`
  - 版は**K100%の黒**で描く。箔の色では入稿しない(型紙であって色指定ではないため)
  - **裏面は通常印刷のまま**。QRを箔にすると光を反射して読み取れなくなる
  - 発注前に「ピンクの箔はあるか」を印刷所に確認する。銀・白なら大抵の店にある
  - 箔は版代が別途かかる(初回のみ)
  - ロゴの最も細い線は 0.4mm 以上あり、箔押しの下限 0.2mm を満たしている

### 案B:黒い紙で作る(検討中)

「少数に良いものを渡して徐々に広げる」という方針が決まったため、
断裁面が白くなる問題を許容しない選択肢を検討する。
モックアップは `public/brand/card-option-black-paper.png`。

| | 案A(データ作成済み) | 案B(要相談) |
| --- | --- | --- |
| 用紙 | 白いマットコート 220kg | ディープマット ブラック 265kg |
| 表 | 黒インク全面 + ピンク箔 | **紙が黒** + ピンク箔 |
| 裏 | 黒インク全面 + カラー印刷 | **白インク印刷のみ** |
| 断裁面 | 白く出る | **黒いまま** |
| ピンク | 表のロゴ + 裏の文字 | **表のロゴだけ** |
| 状態 | すぐ発注できる | LEDAに白インク対応を要確認、データ作り直し |

決めるべきは実質「**裏面のピンク**」と「**黒い断裁面**」のどちらを取るか。
断面の違いは `public/brand/card-edge-comparison.png` を参照。

**案C(両取り)**:黒い用紙に白インクを下地として刷り、その上からカラーを乗せる。
断裁面は黒いまま、裏面にピンクも使える。ただし工程が増えるぶん高くつき、
対応できる印刷所が限られる。LEDAへの問い合わせに可否を含めてある。

案Bは裏面がすべて白インクになるため、階調(グレーの補足文字)が使えず、
文字の強弱は級数と太さだけで作る。ピンクが表のロゴ1点に集約されるので、
ブランドの色としてはむしろ強くなる。

注意点:

- ディープマットは表面が粗く、白インクがやや沈む。**2度刷り**で濃くできる
- QRは**白インクのベタ地に紙の黒を抜き**で作る。箔にはしない(反射して読めない)
- LEDAが白インク印刷に対応しているかは未確認。非対応なら
  箔押しと白インクの両方を扱う「あさだ屋」が代替候補

### 黒ベタの注意

白い紙に黒を全面印刷するので、**断裁面(カードの厚みの部分)は白いまま**になる。
黒い名刺の安っぽさは大抵ここから出る。気になる場合の選択肢:

- そのまま許容する(通常のネット印刷はこれ)
- 黒い紙に白インクで刷る。断裁面まで黒くなるが、白インク対応の店が必要で、
  裏面のデザインを作り直すことになる

また、大きな黒ベタは K100% だけだと薄く見える。入稿時に
**「背景の黒はリッチブラックで」**と伝えると濃く出る。
- 代替:活版印刷(文字が凹む)、エンボス
- 注意:マット黒は指紋が目立つ。気になるならマットPP加工を足す
- 全面黒はムラが出やすい。黒ベタに実績のある印刷所を選ぶ

## 印刷所の選定

候補を2社まで絞った結果、**LEDA(レダ)** を本命とする。

| | LEDA(レダ) | メガプリント |
| --- | --- | --- |
| 入稿形式 | **PDF推奨** | Illustrator AI/EPS・Photoshop PSD |
| 箔と色を別PDFで | **そのやり方を指定している** | Illustrator上でレイヤー分け |
| 塗り足し | 3mm(標準) | 標準より1mm広い独自トンボ |
| ピンク箔 | メタリックピンク / シルキーピンク / ローズゴールド | ピンク箔(注文確定後に追加料金) |
| 最小ロット | 50枚から | 100枚から |
| 価格 | ワンポイント箔押し 50枚 5,170円〜 | 箔押し100枚 1,700円前後 |
| 性格 | 箔押し専門の工房 | 総合ネット印刷。安い・速い |

**決め手は入稿形式。** 手元にあるのはPDFで、Illustratorは持っていない。
メガプリントは安いが、そこにたどり着けない。

LEDAの要件は生成済みデータとそのまま噛み合う:

- PDF入稿 → `card-front-print.pdf` / `card-back-print.pdf`
- 箔と通常印刷は別PDF → `card-front-foil-plate.pdf`
- 裁ち落とし3mm → 97 × 61mm で一致

### 印刷所自身が挙げた懸念(案Aを見送った理由)

> ①デジタル印刷機のため、広範囲のベタ塗りはムラが発生する可能性
> ②箔押しは手作業のため、上下左右1mm程のズレが発生する可能性
> (通常印刷との間に箔押しがくるデザインのため、ズレると目立ちやすい)

表面は全面黒ベタの中央にピンク箔 —— ①②の両方を踏む。
**黒い紙(案B)なら背景を刷らないので、どちらも回避できる。**

### 見積もり(角丸なし・ネオンピンクあり)

ディープマット ブラック 265kg / 箔1版 メタリックピンク / 50枚 /
ホワイト印刷 / スペシャルトナー2色使用 → **12,100円**(税込・送料別)

角丸は **R3 か R5 しか選べず**(R1.5mm は不可)、1,815円。
黒い紙なら角が傷んでも白い断面が出ないため**見送った**。

## 線の太さ —— 1文字ずつ測る(0.2mm 基準)

⚠ **行ごとにまとめて測ると、細い文字が平均に埋もれる。**
最初その測り方をして「全て 0.2mm 以上」と誤って判断した。
本人が「@ が細く見える」と指摘して発覚。**1文字ずつ、単独で描いて測ること。**

測り方: その文字だけを4000dpiで描き、距離変換で中心線の太さを出す。
値は「細い所(10パーセンタイル)」。`scripts/` を変えたら測り直す。

### 直したこと(2026-08-18)

「中野 修敬」とタグラインの**太さを1段(500→600)上げた。大きさは据え置き。**
句点1文字のために行全体を大きくするのは割に合わないと判断した。

| | 直す前 | 直したあと |
| --- | --- | --- |
| 中野 修敬(いちばん細い「修」) | 0.190mm | **0.203mm ✓** |
| タグラインの「で」の濁点 | 0.167mm | **0.185mm** |
| タグラインの句点「。」 | 0.152mm | **0.165mm** |
| **「ありがとう」の5文字** | **すでに 0.200〜0.241mm ✓** | 触っていない |

### 意図的に 0.2mm を下回らせている箇所

**本人の判断:「意味を運ぶ文字」と「決まりが運ぶ文字」を分ける。**

| 文字 | 値 | 残した理由 |
| --- | --- | --- |
| 「@」 | 0.175mm | そこに @ が入るのは決まりごと。かすれても読み違えない |
| 「g」「e」(メール内) | 0.178 / 0.190mm | 同上 |
| 句点「。」 | 0.165mm | 丸が何かあれば足りる。消えても「でした」は読める |
| 「で」の濁点 | 0.185mm | 唯一「印刷ミスに見える」種類。1段太くして4割改善させた |

## QRの作り方(2026-08-18 確定)

- **ベクターで描く。** `qr-roguepink.png` から25×25のマス目を読み取り、四角形として置く
- 白インクのベタ地(21.17 × 20.9mm・角丸1.2mm)に、**紙の黒を抜いて**表現する
- **大きさは「コード本体」で指定する(15.80mm / 1マス 0.632mm)。**
  まわりに必要な余白4マスは、**白いプレートがそのまま兼ねる**
- 刷り上がり(白インク=白 / 紙=黒)を機械で読ませて、
  **カメラ 5〜12px/mm のすべてで `https://roguepink.com` と読めることを確認済み**
- ✅ **2026-08-18、本人が実物大で印刷して手元のスマホで読み取りテストを実施。確実に読めた。**
  テスト用紙は `scripts/build-test-sheet.py` で作れる(`public/brand/qr-test-sheet-a4.pdf`)

## LEDA からの指摘(2026-08-19)と対応

### 1. 箔版の「R の下部が擦れている」→ 直した

原因は**ロゴが画像だったこと。**

`logo-transparent.png` は 692×623px しかなく、名刺に置くと **489dpi 相当**。
縁に半透明の画素が残っていて、それをグレースケールに落とすと**灰色**になる。

**箔押しは型を押しつける加工なので、版に濃淡は存在できない。** 黒か白しかない。
灰色の部分は、箔が乗るとも乗らないとも言えない場所 —— それが「擦れ」に見えていた。

測ったところ、旧データには **形の内側に灰色の画素が 13,805 個**あった。
さらに R マークの下端(y=466〜486)に **0.09〜0.30mm の白い粒が 16 個**混ざっていた。

対応として `scripts/trace-logo.py` を新設し、**輪郭を数式(ベクター)に置き換えた。**

1. 半透明を切り捨てて白黒にする(ここで濃淡が消える)
2. 0.5mm 未満の粒と穴を取り除く(文字のふところなど大きい穴は残す)
3. 4倍に引き伸ばしてから輪郭を追い、階段状のギザギザをならす
4. potrace でベジェ曲線にして `public/brand/logo-foil.pdf` に書き出す

| | 旧(画像) | 新(輪郭) |
| --- | --- | --- |
| 版の中の灰色 | 13,805px | **0px** |
| R 下端の白い粒 | 16個 | **0個** |
| 拡大したときの縁 | 489dpi でギザギザ | **なめらか(解像度に依存しない)** |
| 元の形との差 | —— | 0.159%(縁が1画素ぶん整っただけ) |
| 線の太さ(下位10%) | —— | 0.762mm(LEDA 基準 0.2mm を満たす) |

**`card-front-foil-plate.pdf` のみ差し替え。**
`card-back-white.pdf` と `card-back-pink.pdf` は 1200dpi で比較して**1画素も変わっていない**ため、送り直す必要はない。

### 2. 「黒い紙にネオンピンクは色が沈む」→ 検討中

LEDA からの提案は、**裏面のピンクもメタリックピンク箔にする**というもの。

| | いまの案(ネオンピンクのトナー) | LEDA の提案(裏も箔) |
| --- | --- | --- |
| 見積 | 12,100円 | **10,450円**(スペシャルトナー2色 1,650円が消えるため) |
| 色 | 紙の黒が影響して**沈む** | 表の箔と**同じ発色** |
| 位置の精度 | 白と同じ機械で刷るので**正確** | 箔は手作業。**上下左右 1mm ほどズレうる** |
| 細い文字 | 多少かすれても出る | **出ない恐れ**(箔は転写するかしないかの二択) |
| 質感 | 白い文字と**同じマット** | 白い文字の隣で**ピンクだけ光る** |

裏面はピンクと白が**縦に交互**に並び、左端が全部 7.0mm に揃っている。
1mm ズレると**その揃いが崩れて目立つ。**LEDA 自身も
「通常印刷との間に箔押しがくるので若干のズレは発生する可能性がございます」と書いている。

## 再点検(2026-08-19・2回目)—— スレを徹底的に潰す

「本当にスレが無いのか、特に QR を確実に」という指示で、もう一段深く見た。
`scripts/preflight.py` は **71項目**になった。

### ★ QRの中に、細いスジが走っていた

**いちばん重い発見。** QRの白抜きは、暗いマスを1つずつ別々の四角として
「白で塗りつぶす」作り方だった。隣り合う四角のつなぎ目には中間調が残り、
印刷機がぼかしてから白黒に落とすと、**暗いマスの中に細い線が走る。**

2400dpi で測ったところ、**暗いマスの内側に 19,670画素の中間調**があった。
ぼかしを切って描いても、**QRの中に1本、0.011mm の縦スジ**が実際に残っていた。

直し方は「白を上から塗る」のをやめ、**外枠と穴を1本の道として一度に塗る**こと
(奇偶ルール)。横に続くマスは1つの長方形にまとめてある。

| | 前 | 後 |
| --- | --- | --- |
| 暗いマスの内側の中間調 | 19,670px | **0px** |
| 白インクの内側の中間調 | 513px | **0px** |
| `card-back-white.pdf` の容量 | 90.2KB | **41.5KB** |

### ★ 色が RGB で書かれていた

「グレースケール(黒1色)」と申告していたのに、PDF の中身は **DeviceRGB**
(`0 0 0 rg`)だった。見た目は同じでも、印刷所が CMYK に変換するときに
リッチブラックになりうる。**申告と中身が食い違っていた。**

色の指定をすべて1つの数字(`g` = DeviceGray)に変え、`0` と `1` しか
使わないようにした。埋め込んだロゴの中まで確認済み。

### QRの確かさ —— 3つの角度から

1. **型式情報を規格どおりに復号**した。誤り訂正 **レベルM**(約15%まで復元可能)
2. **劣化を再現してマスを1つずつ読み直した。**白インクが 0.15mm にじんでも、
   0.15mm やせても、0.5mm ぼけても **間違い0マス**(許容93マス)
3. 読み取りソフト(OpenCV)は当たり外れがあるので、**マスの中心を直接見る**方法で判定している

### 縁のうねりを測った

ロゴは元が画像なので、輪郭に直しても細かいうねりが残る。輪郭を1周たどって
なめらかにした線からのズレを測った。

| | 平均 | 上位10% |
| --- | --- | --- |
| 表ロゴ | 2.5μm | 8.0μm |
| 裏ワードマーク | 2.8μm | 8.2μm |
| (参考)本物のフォント | 1.2μm | 2.6μm |

**箔押しが出せる下限は 200μm。**うねりはその 1/25 で、印刷では再現されない。

引き伸ばし8倍・ぼかし・曲線の当てはめを緩める組み合わせも試したが、
8.2 → 6.9μm しか縮まらず、代わりに元の形からのズレが 0.64% → 0.67% に増える。
**割に合わないので、いまの設定のままとした。**

### 小さな粒・穴の走査

3つの版すべてで、0.15mm 未満のゴミと穴を探した。見つかったのは
1200/2400/4800dpi で**常に「ちょうど1画素」の点**で、解像度を変えると
位置も大きさも変わる —— **データではなく描画のクセ。**4800dpi では消える。

### 結果

**71 / 71 項目 OK。**形は前回の入稿データと同じで、変わったのは
QR の中の 0.011mm のスジが消えたことと、色指定が DeviceGray になったことだけ。

- **ワードマーク** —— 画像を捨てて Montserrat Bold から組む。
